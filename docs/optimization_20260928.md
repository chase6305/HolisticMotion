# 约束报告与舍入时钟优化（2026-09-28）

本轮于 01:36:09 UTC 开始，持续优化三小时。对照分支起点为 `515d8ce`，
其中生产实现为 `866355a`；本轮最终生产实现为 `7de6b31`。以下性能是相对 `866355a` 的增量比较，没有重新测量原始 `main`。

## 实现与适用范围

- 每次约束报告在均匀采样循环中维护一个局部求值器，复用当前内置五次曲线的固定控制差值。
  切换几何段时先销毁求值器，再更新持有控制点的强引用；报告之间不保留缓存。
- 只缓存精确的内置曲线类型。派生段继续执行全部虚函数，位置非有限时仍抛出异常，
  无效曲线在访问控制点之前校验。阶段端点继续走原来的单侧求值，连续性容差和采样密度不变。
- 报告实现移到单独的编译单元，共用私有链式法则头文件，保留全部表达式及极端值回退。
  为十个既有流形运算函数增加标准 `inline` 声明，未改变公式、对象布局或公共 API。
  不使用强制内联和编译器专用属性；实际收益与编译器和工作负载有关。
- 梯形剖面的短加速阶段被绝对时钟舍入吞掉时，仍先尝试原来的合并和降低峰值修复。
  两者都失败后，才在初选中间时间和末时间附近至多四个 ULP 内寻找两个恒加速度阶段。
  根据实际可表示的阶段时长求共同速度，保持请求的起止位置和速度，并检查每个阶段的
  位移、速度、加速度及时间预算。样条的 `acceleration / 2` 系数若会丢失有效值，则拒绝该候选。
  不放宽旧误差预算，也不掩盖报告告警。
- Python 关节和笛卡尔均匀采样在分配前检查最大输出数组的索引和字节数是否可表示。
  超大数量一致抛出 `ValueError`；正常输入的返回形状和数值不变。
  批量结果直接写入 NumPy 拥有的缓冲区，省去临时 Eigen 结果的完整复制；
  保持数组布局、可写性、独立性和生命周期。笛卡尔采样的纯 C++ 循环释放 GIL，
  使其他 Python 线程可以继续运行。
- 查询与报告基准增加 SE3 工况，CSV 新增 `group` 列。没有新增运行时依赖；碰撞仍为可选组件，
  测试只使用合成路径和临时 URDF，不需要外部机器人资产或下载。

## 未采用的方案与限制

将缓存同时扩展到报告的阶段端点，虽然使部分 SE3 小样本报告更快，却使 Rn2 报告变慢，
因此未采用。报告与状态查询留在同一大型编译单元的方案造成 7 维构造和查询回退；
拆分实现并恢复通用 `Rplus` 的内联声明后，消除了这项明显退化。归档保留这些试验的原始数据。
当前 Release 静态库文件从 **18,687,322 增至 19,454,624 字节（约 4.1%）**；
归档保留各目标文件的 `size` 输出。静态库成员总量包含最终链接可能合并或删除的内容，
不能直接当作消费程序的代码体积或运行时内存增量。
实际链接的查询/报告基准文件分别从 6,116,760 / 6,116,696 增至 6,264,976 / 6,314,064 字节
（约 2.4% / 3.2%），两者的 BSS 均保持 192,032 字节；这只描述这两个调用程序。

保留的连续性告警仍属于失败。绝对时间的浮点分辨率会限制短阶段的实际积分精度；
本轮只恢复能在旧预算内表示的被拒绝剖面。离散采样不能证明连续时间限位或碰撞安全。
SE3 差分测试验证实现结果一致，不构成对任意位姿路径物理导数的独立证明。
没有验证 CUDA/GPU 或机器人硬件，也没有宣称所有工作负载都加速。
