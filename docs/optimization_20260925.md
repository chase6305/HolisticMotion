# 三小时数值稳定性与查询性能优化（2026-09-25）

工作基于 `e806b55`，分支为 `perf/numerical-query-optimization`。
本轮集中处理规划、SRS 零空间、球体碰撞查询和关节轨迹；没有改变公共函数签名、
引入运行时依赖或自动下载机器人模型。测试使用临时 URDF，工作区 `assets/` 未纳入提交。

## 修复范围

| 模块 | 已复现的问题 | 修改后的行为 |
| --- | --- | --- |
| 路径优化 | 极小权重的倒数溢出；禁用的几何项仍参与运算；全局大常数掩盖局部改善，甚至允许上坡或使最终统计变负 | 保留相对下降方向；跳过零权重项；只比较受影响的局部目标；最终成本从缓存重算 |
| 采样规划 | 小权重把未校验的障碍间隙误当成连接；捷径去重丢失终点；重复目标样本占用大量节点 | 依据实际到达状态连接；按坐标去重；复用重复状态并保留父节点选择和重连 |
| SRS / 零空间规划 | 薄 SVD 矩阵乘法维度错误；起点不满足关节范围；大偏好方向归一化变零 | 直接用保留的右奇异向量做投影；校验硬件和用户范围；缩放后归一化 |
| 球体碰撞 | 每次查询刷新所有 frame，包括与球体无关的传感器和工具 frame | 每次只刷新球体所属的不同 frame，继续共享完整关节运动学计算 |
| 路径和样条 | 短末段被过滤；禁用微小混合段后留下连接间隙；导数重复计算 | 保留非零终点位移，在裁剪直线前禁用微小混合段；合并三次样条导数求值 |
| 轨迹限制 | 短曲线阶段的峰值被全局采样漏掉；每个采样点反复计算导数利用率的根 | 直线阶段检查解析极值，曲线阶段至少检查 65 个局部点；汇总利用率后统一计算缩放系数 |
| Double-S | 舍入级速度上限差异和微小平台造成失败；末段降速未回传导致速度跳变；回溯把实际加速度误当成允许上限 | 保留舍入等价的速度；积分前消除舍入平台；向上游回传必要降速；使用已配置的加速度能力 |

末段连续性问题的独立审计包含 200,000 组输入：修复前有 435 组速度跳变、
2 组构造失败；全部修复后 200,000 组通过。一个三路点例子在连接处瞬间降低
约 0.614 的关节速度，但旧的采样限值报告仍返回 `within_limits=True`。
现在该例子同时满足限值、速度连续和加速度连续检查。

后续另一个种子的一百万组审计中，999,997 组通过，3 组梯形轨迹被拒绝。
三例在本轮起点版本上也失败，原因是曲线和直线速度上限的舍入差异导致极短变速段。
梯形剖面现按原始上限采用 256 倍机器精度的相对预算；三例均已回归通过，
并继续检查终点、速度/加速度限值和速度连续性。其后 300,000 组梯形专项审计
（种子 `20260929`，统一使用梯形剖面）中 299,999 组通过，仍有 1 组因极短变速阶段
的时间戳精度限制被拒绝；该例在原始版本上也失败。完整输入保存在
[`trapezoidal_timestamp_rejection.json`](../benchmarks/fixtures/trapezoidal_timestamp_rejection.json)，
可传给 `hm.RnTrajectory(**json.load(open(path)))` 复现。未把该构造拒绝计为通过。

后续两小时优化已修复该保留用例，并重跑上述 300,000 组专项审计，全部通过。
此处保留原轮次结果；当前修复、压力分布下仍存在的拒绝及验证结果见
[追加优化报告](optimization_20260925_followup.md)。

另修复了 `main` 已有的 CI 环境问题：两个测试任务显式安装已声明的 NumPy 依赖，
并在测试环境安装场景样式及体素拟合测试需要的可选 trimesh、SciPy；
文档任务从 `pyproject.toml` 安装文档及 Python 运行依赖，使用现有的原生扩展 mock
构建 API 文档，避免触发需要 Eigen/Conan 的原生 wheel 编译。

## 配对性能

使用 GCC 12、Release 库、`-O3` 基准程序、固定 CPU 和确定输入。预热后取中位数；
球体查询交替执行三组前后配对，其余表格数据为六组配对。以下结果针对具体场景，
不代表所有机器人或实机吞吐。
球体结果包含 Python 绑定和结果转换。RRT* 表格隔离比较重复状态复用前后的实现，
两侧已经包含本轮的连接正确性修复；其他模块的前后版本对应各自修改前后。
完整轨迹构造、查询对照链接本轮起点 `e806b55` 的库。

| 测量对象 | 修改前 | 修改后 | 说明 |
| --- | ---: | ---: | --- |
| 14 球、额外 256 个固定 link：最小距离 | 3.954 µs | 1.150 µs | 3.44 倍 |
| 同模型：布尔碰撞 | 3.613 µs | 0.863 µs | 4.19 倍 |
| 同模型：距离及梯度 | 5.477 µs | 2.605 µs | 2.10 倍 |
| 2 维混合周期关节 RRT*，目标采样概率 95% | 50.443 ms | 2.653 ms | 19.0 倍，依赖大量重复目标样本 |
| 7 维混合周期关节 RRT*，目标采样概率 95% | 21.583 ms | 4.284 ms | 5.04 倍 |
| 7 维混合周期关节 RRT*，默认目标概率 5% | 65.802 ms | 61.808 ms | 1.06 倍 |
| SRS 正常构型零空间投影 | 4.643 µs | 4.176 µs | 1.11 倍 |
| 7 维、4 路点、无混合：Double-S 构造 | 275.912 µs | 5.460 µs | 50.5 倍 |
| 7 维、64 路点、无混合：Double-S 构造 | 513.181 µs | 119.696 µs | 4.29 倍 |
| 7 维、64 路点、混合 0.005：Double-S 构造 | 993.415 µs | 1857.014 µs | 增加约 87%，提高曲线检查密度 |
| 7 维、64 路点、混合 0.005：梯形构造 | 711.196 µs | 1472.637 µs | 增加约 107% |

| 独立样条 jet，16 个阶段 | 8.843 ns | 4.938 ns | 1.79 倍，不含几何映射 |

保持检查密度后，再把平方根和立方根计算移到采样归约之后，使 16 个构造场景
相对汇总计算之前再快约 1.06–1.39 倍。单独用 200,000 组输入对照这一步：196,992 组
输出逐位一致，其余 3,008 组的时长最大相对差为 `4.33e-16`。进一步核对这 3,008 组
的 14,354,392 个位置和导数分量，`abs(after-before)/max(1,abs(before))` 最大为
`4.32e-13`。浮点库根函数的舍入可以改变末位，不声称所有结果逐位一致。

路径优化在 24 种输入组合上的配对中位耗时比（后 / 前）：长度与平滑项同时启用
约 1.001，仅长度项约 0.907，仅平滑项约 0.965；统计值和路径校验和相同。

长混合路径的构造存在明确开销：曲线阶段的最低采样密度由 9 提高至 65。
该调整修复了曾漏检约 0.78% 加速度超限的案例，不能把直线路径的加速外推到
所有曲线工作负载。样条单独求值与完整轨迹查询也应分别解释。

RRT* 的 18,000 组前后对照保持成功状态、迭代数和路径长度完全一致，删除连续
重复点后的路径在 `1e-9` 容差内相同；总存储节点从 9,834,811 降至 6,854,159。
其他修复可以改变轨迹时长：2 维、4 路点查询基准原先在末段存在速度跳变，
修复后时长由 2.991 s 增至 3.989 s；恢复可用加速度也可以缩短回溯后的轨迹。
因此不以这些输入的新旧校验和相同作为正确性要求；表中的 7 维查询保持时长和
校验和一致。新查询基准同时输出限值与连续性诊断。

本机将核心 Python 和原生碰撞分开验证，避免 pip Pinocchio 4.1 与 Conan
Pinocchio 3.8 同进程的 ABI 冲突。碰撞 sanitizer 构建用
`-DEIGEN_MALLOC_ALREADY_ALIGNED=1` 匹配预编译 Conan 依赖的 Eigen 分配方式，
保留 ASan、UBSan、LeakSanitizer 和 Eigen 断言；未给生产目标添加该配置。

曲线限值和阶段连续性审计仍属于数值采样验证，不构成连续可行性的证明。
非零 C++ 起始速度不可行时直接返回无效轨迹，避免回溯空容器；无法抵达速度上限的
短凹形超速边界组合明确拒绝，保留可行的长凹形剖面。
没有运行 CUDA/GPU 或实机测试；这些结果也不意味着任意接近浮点极限的规划
坐标和权重组合都能求解。外部机器人资产路径仍由调用者显式提供。
