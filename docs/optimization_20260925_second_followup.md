# 第二轮两小时追加优化（2026-09-25）

本轮从 `219fedd` 接续[上一轮报告](optimization_20260925_followup.md)，工作窗口为
北京时间 18:18–20:18。改动提交至 `perf/numerical-query-optimization`，并更新面向
`main` 的 [PR #3](https://github.com/chase6305/HolisticMotion/pull/3)。

## 改动及回归依据

| 问题 | 处理 |
| --- | --- |
| 曲线与相邻直线各自计算速度上限，舍入差异触发拒绝或不必要的回溯 | 在构造剖面前，同时以两侧直线的上限约束曲线连接速度 |
| 合并极短梯形加减速阶段时，平均速度变化对应的时间修正被误拒绝 | 按实际速度差计算时间预算，继续检查积分位移与加速度 |
| 绝对间隔 `0.01` 的曲线预采样随坐标尺度无限增长 | 普通网格保持原样；长度超过 `40.96` 时使用最多 4096 个归一化区间，包含端点，随后仍检查组合轨迹限位 |
| Double-S 的四次幂中间量溢出，反复降低加速度也增加构造开销 | 静止到静止使用解析解；一般凸形速度剖面直接求可行速度增量，避免微小增量被非零端点吞掉 |
| 近单向过渡产生极小的反向加减速阶段 | 在可用距离内拟合单向过渡，限制实际加速度与 jerk，并核验实现的速度差；零长度剖面明确拒绝 |
| 直线时间阶段因路径位置舍入提前使用曲线导数，产生虚假的 jerk 峰值 | 对归属明确、单调且落在对应几何范围内的直线阶段保留几何段；跨曲线阶段继续按位置查询与细分 |

本轮没有新增公开接口、对象数据成员或运行时依赖。碰撞组件保持可选；测试使用
合成路径和临时 URDF，没有增加机器人资产或隐式下载。

原来保留的
[`trapezoidal_cap_rejection.json`](../benchmarks/fixtures/trapezoidal_cap_rejection.json)
已经修复；另保留了精简的
[`double_s_join_cap.json`](../benchmarks/fixtures/double_s_join_cap.json)。连接回归覆盖
正向、反向和三种尺度。Double-S 标量回归在 `1e-200` 至 `1e200` 的共同尺度下，
用独立的长双精度参考时长和逐相位积分检查边界与限位。

大坐标轨迹回归覆盖两种剖面及 `1`、`1e4`、`1e6`、`1e12`、`1e100` 五种尺度。
在其中的 Double-S 案例中，旧的几何归属使放大 `1e6` 后的运动时长从约
`7.25760655 s` 增至 `9.14401126 s`；修复后恢复相同时长。这是该案例中虚假
jerk 峰值造成的约 26% 额外减速，不是全部路径的通用加速比例。

## 配对性能

以本轮起点 `219fedd` 为基准，使用 Ryzen 9 9950X、GCC 12、Release `-O3`，
固定 CPU 6，六组交替前后顺序的运行，取各次中位数的中位数。长时间审计及包构建
分配到其他物理核。构造计时不含路径几何创建；输入及限位相同，修正后的运动时长
和时间相位比例可能变化。

| 7 维构造场景 | 修改前 | 修改后 | 加速比 |
| --- | ---: | ---: | ---: |
| 4 路点，无圆滑，Double-S | 4.704 µs | 3.848 µs | 1.22 倍 |
| 64 路点，无圆滑，Double-S | 103.235 µs | 79.196 µs | 1.30 倍 |
| 4 路点，圆滑 0.005，Double-S | 101.197 µs | 91.984 µs | 1.10 倍 |
| 64 路点，圆滑 0.005，Double-S | 1620.939 µs | 1015.138 µs | 1.60 倍 |
| 64 路点，圆滑 0.005，梯形 | 930.532 µs | 912.543 µs | 1.02 倍 |

32 个构造场景的加速比为 **0.96–1.60 倍**，没有宣称全部场景加速；16 个完整或
独立状态查询场景约为 **1.01–1.09 倍**。7 维长圆滑 Double-S 案例的运动时长
减少约 16.1%，这是剖面及限位修正的结果，不能解释为仅更快地求出完全相同的输出。

大坐标采样另以四个二维路点测试，各坐标、速度、加速度、jerk 限位及圆滑容差
同比放大，固定 CPU 7，预热后取十次中位数。尺度 `1e4` 下：

| Python 构造 | 修改前 | 修改后 | 加速比 |
| --- | ---: | ---: | ---: |
| 梯形 | 58.827 ms | 0.563 ms | 104.4 倍 |
| Double-S | 57.621 ms | 0.557 ms | 103.5 倍 |

该结果反映消除随单位尺度增长的采样量，不代表普通长度路径的收益。

另对照 `main`（`e806b55`）的原始头文件和静态库测量整个 PR：7 维、4 路点、无圆滑
Double-S 构造约为 **71.1 倍加速**，4 路点圆滑场景约为 **4.21 倍**。
7 维、64 路点的圆滑 Double-S 为 `996.592 → 1018.138 µs`，仍约慢 **2.2%**；
同场景梯形为 `702.005 → 909.748 µs`，仍约慢 **29.6%**。更密的局部限位检查仍有
代价；上一轮记录的长圆滑 Double-S 约 59% 额外开销已大幅降低。

## 剩余边界

上述十万组压力输入仍拒绝 8 条梯形轨迹。完整输入之一保存在
[`trapezoidal_clock_precision_rejection.json`](../benchmarks/fixtures/trapezoidal_clock_precision_rejection.json)，
对应种子 `20261002` 的第 `567` 例。其绝对时间约为 `273.5689 s`，时钟间隔约
`5.68e-14 s`，计划加速段仅约 `2.18e-14 s`。合并后的路径位移误差约
`7.17e-15`，超过约 `3.72e-15` 的一致性预算，因此仍拒绝。

这表示当前双精度时间表示及分段构造没有通过一致性检查，不等于输入在物理上
不可行。没有为减少拒绝计数而放宽这一位移预算。成功与拒绝分开统计，采样审计
不能证明连续时间的所有约束；CUDA/GPU 与实机没有在本轮验证。

## 复现

```bash
# 在已有 Conan/CMake 配置中开启独立诊断程序
cmake -S . -B build/cmake -DHOLISTICMOTION_BUILD_BENCHMARKS=ON
cmake --build build/cmake --target double_s_profile_audit -j2
build/cmake/double_s_profile_audit 2000000 20261010

PYTHONPATH=build/install python benchmarks/trajectory_audit.py \
  --distribution stress --seed 20261002 --cases 100000 --samples 1001 \
  --phase-samples 129 --check-continuity
PYTHONPATH=build/install python benchmarks/trajectory_audit.py \
  --distribution stress --seed 20261002 --case-index 567 --samples 1001 \
  --phase-samples 129 --check-continuity

ctest --test-dir build/cmake --output-on-failure
PYTHONPATH=build/install python -m pytest tests/python -q
conan create . --no-remote -o '&:with_python=False' -o '&:with_tests=True' \
  -o '&:with_cuda=False' -o '&:with_collision=False'
# 碰撞配置改为 with_collision=True；共享库配置增加 shared=True
./scripts/docs.sh
```

压力输入复现须使用上述 NumPy 版本；不同版本及浮点平台可能改变临界输入。
诊断程序对构造拒绝和不变量失败均返回非零状态，拒绝不计作审计成功。
