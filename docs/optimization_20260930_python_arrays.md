# Python 轨迹数组分配优化（2026-09-30）

本轮增量基线为 `db1c4ad`，实现提交为 `477fc8c`。状态查询、均匀采样和约束报告
构造 NumPy 返回数组时，以栈上的固定长度 shape/stride 描述替代临时堆容器。
NumPy 继续分配并拥有可写数据；数值、形状、步长、C/F 连续性和返回值生命周期

## 分配次数与实现边界

桥接函数复用 pybind11 的 NumPy API 加载器，调用与其数组构造函数相同的
`PyArray_NewFromDescr`。无需 NumPy 头文件，也未增加运行或构建依赖。
描述对象的引用在调用时交给 NumPy；创建失败时传播原 Python 异常。
既有样本数量校验、GIL 释放范围、采样网格及 C++ 算术均不变。

| 每次调用减少的分配 | Rn | SE3 |
| --- | ---: | ---: |
| state | 8 | 6 |
| sample_uniform | 11 | 11 |
| constraint_report | 16 | 6 |

该计数来自最终安装产物，与性能计时分开运行，覆盖两种速度剖面、Rn 的
1/3/7/14/32 维和 SE3，以及报告/采样的 2/65/2001 点。它表示稳定的最小分配次数
差值；NumPy 缓存可能影响某次调用的绝对分配数量。
桥接使用 pybind11 的内部 API，升级该依赖时应继续运行兼容性与所有权回归。
本轮验证 pybind11 2.13.6/3.0.1 与 NumPy 1.23.5/2.2.6 的全部四种组合。

## 未采用的实验与复现

时钟相邻分段查询与端点分支没有取得可接受的整体结果。高维采样按 16 个状态
分块写入的原型，在探索测量中使 20001 点均匀采样的工况中位数增加约 31.6%，
未采用。日志对象引用缓存则在两个独立 `RTLD_LOCAL` 动态库间破坏接收器隔离：
基线各收到一条日志，缓存原型将两条都发送给第一个接收器，因此淘汰。
报告字典改用直接 `PyDict_SetItem` 的独立原型，2 点报告中位数仅下降约 1.6%，
同时 SE3 double_s 的 2001 点报告增加约 3.0%；收益不足以支持再增加一层桥接，
本轮未采用。早期整进程计时曾出现宽幅正负波动；这些探索结果与最终常驻进程数据分开保存。

