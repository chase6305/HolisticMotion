## 问题与实现

长匀速阶段之后的短加速度或 jerk 阶段，实际可表示的绝对时间差可能与名义时长不同。
原来按名义时长计算的导数，在实际样条时间轴上积分后不能准确连接下一阶段。
例如一维 Double-S 路径 `[0, 10000]`、速度上限 `0.1`、加速度上限 `1`、
jerk 上限 `1e6`，基线原生报告的最大加速度跳变约为 `6.80e-6`，超过 `1e-7` 容差。

- Double-S 在检测到时钟舍入足以超过原导数误差预算时，按实际可表示的时间差
  重新求两个受 jerk 限制的斜坡及其共同速度。斜坡位移写成起止速度的线性组合，
  由总位移求共同速度，再投影到原速度、加速度和 jerk 约束的交集。
  长双精度仅用于中间计算；候选必须重新通过实际存储的 `acceleration / 2`、
  `jerk / 6` 系数积分检查。
- 阶段时长先向上舍入到可表示的时钟，随后至多尝试增加七个时钟步；
  Double-S 的匀速末点还允许减少一至四步。总末时间偏移不超过
  `64 * epsilon * max(abs(start), abs(planned_end))`。
  限位、位置积分和导数连续性预算不放宽，失败候选不替换原剖面。
- 路径回溯导致整个 Double-S 剖面移动到新时间原点时，重新检查时钟舍入，
  并以原剖面已经达到的导数上限执行相同拟合。
- 梯形剖面按实际加速、匀速、减速时长求共同速度，再检查每个恒加速度阶段。
  保留原有短过渡的末速度调整和全局时间缩放语义；这种分支原先可能使用超过
  配置值的局部减速度，新拟合不会超过它原本使用的值。
  上一轮针对被吞掉的斜坡所做的合并、降峰和两阶段恢复顺序保持不变。
- 候选阶段位置限制在指定起止位置之间，并要求单调。零时长阶段不能改变状态。
  这一检查避免终点附近一两个浮点步的超越形成微小倒退，进而丢失直线阶段的
  几何归属，在真正停车前提前使用反向线段的切向量。
- 不改变公共 API、对象布局、依赖或自定义几何的虚函数语义。碰撞仍是可选组件，
  全部新增测试使用合成路径，无需机器人资产或下载。

第一版拟合 `5f4d0c8` 在密集审计中暴露了上述几何归属回归；报告审计也发现相关告警。
定位后增加了公开 Python 回归，确认修复前失败、修复后通过，并以 `19e6c1d`
重新运行全部最终语料。中间结果保留在归档中，不能作为最终通过数。

## 差分结果及保留限制

20,000 条普通/压力 Rn 和 100,000 条缩放 Rn 均可构造。拟合会改变阶段时间和状态，
因此不要求与基线逐位相同。对签名变化的输入，额外配对比较 17 个归一化时间点、
时长、断点数量及报告，检查新拒绝、非有限状态和新报告失败。

普通语料有 14,446 条签名完全一致、5,554 条改变；缩放语料为 50,550 和 49,450 条。
改变的输入没有新增拒绝、非有限值或报告失败。普通语料的最大相对时长变化约
`4.50e-12`；缩放语料约 `2.47e-5`，后者最大归一化位置差约 `3.49e-4`。
速度、加速度、jerk 按各自配置限位归一化后的最大差值分别约
`7.85e-4`、`6.05e-4`、`3.10e-4`。位置以 `max(1, generator_scale)` 归一化，
时长以两版本较大值归一化。这不是全部状态仅改变末位浮点数的声明。

普通和缩放语料分别有 908、10,022 条断点数量变化，包含极短阶段出现或消失。
对上述各指标变化最大的七个不同输入，增加到 100,001 个均匀点和每阶段
1,025 个点复核，最终版本全部通过；输入、配对偏差和检查结果均保留。

SE3 的 2,000 条普通语料签名全部一致；4,000 条宽尺度语料保留原来的 6 条拒绝，
20,000 条报告语料保留原来的 1,398 条拒绝。宽尺度及报告语料分别有 5、1,822 条
签名变化。对后者增加逐项诊断后，确认没有新增
有限值、限位或连续性失败；但仍有基线已有的 83 条速度连续性告警
（Double-S 27 条，梯形 56 条）。Double-S 没有加速度连续性告警；
梯形的加速度跳变是其预期特征。上述 SE3 语料不能表述为全部通过。

83 条告警均来自带混合曲线、姿态反复接近 180° 的笛卡尔路径。两条代表案例
进一步缩减到各 4 个途经点：断点两侧标量路径速度一致，直线与五次曲线的
切向量差范数约为 1.414，基线与当前版本都存在。缩减输入及边界诊断保留在归档中，
供后续几何连接分析；本轮未修复它们，也未证明所有 83 条告警具有完全相同根因。

## 性能

AMD Ryzen 9 9950X / x86-64，GCC 12.3.0，库为 Release `-O3 -DNDEBUG`，
调用端为 `-O2` 且保留断言。在 CPU 15 上执行八轮交替次序的基线/最终版本配对，
取每轮内部中位数的中位数。计时时暂停本轮自己的后台审计；没有停止共享主机上
其他用户任务，未控制其负载和 CPU 频率。全部原始配对保留，耗时不作为 CI 门槛。

速度比定义为基线耗时 / 最终耗时，小于 1 表示变慢。

| 矩阵 | 工况数 | 中位数速度比范围 | 最慢相对变化的工况：之前 → 之后 |
| --- | ---: | ---: | --- |
| 构造 | 32 | 0.982–1.026× | Rn2 / 64 点 / 不混合 Double-S：57.965 → 59.002 µs |
| 状态与分项查询 | 20 | 0.995–1.008× | SE3 / 4 点 / 组合状态：553.704 → 556.261 ns |
| 五次曲线报告 | 30 | 0.965–1.026× | Rn20 / 64 点 / 2,001 样本：389.383 → 403.344 µs |
| 限位构造分解 | 10 | 0.991–1.000× | SE3 / 64 点 / 尺度 1：2164.345 → 2185.029 µs |
| 直线及二次曲线报告 | 60 | 0.947–1.041× | SE3 / 64 点 / 二次混合 / 2 样本：0.341 → 0.360 µs |

二次曲线报告基准使用自定义线性时钟，而非内置 Double-S。构造时长及校验和、
全部报告校验和与限位校验和一致；两个查询工况的数值校验和变化，符合此次
标量时钟修复会改变状态的性质。没有把它们归为逐位等价。

五次报告最慢工况的八个单独配对速度比为 0.942–0.973×；SE3 四点组合查询
有一个 0.841× 的较慢配对，中位数比较为 0.995×。没有删去这些测量，
也没有单独归因主机波动与代码布局。全部配对和各工况分布在归档中。

另外用 12 个长匀速/短斜坡输入直接计时低层剖面构造，分别覆盖三个 jerk 或
加速度上限及两个绝对起始时间，执行相同的八轮交替配对。六个 Double-S 输入
从约 183–186 ns 增至 487–494 ns，六个梯形输入从约 70.6–70.8 ns 增至
173–177 ns；速度比分别为 0.371–0.378× 和 0.399–0.410×。这量化了触发拟合
分支时的额外成本。12 条基线都超过独立积分预算，最终版本全部满足原预算，
因此不是两个数值等价实现的纯加速比较。

本轮重点是减少时钟精度造成的错误，不宣称整体速度提高。上一轮 Python 批量内存
和 GIL 的优化未改动，本轮没有重新测量那部分性能；其历史数据见
[上一轮报告](optimization_20260928.md)。
