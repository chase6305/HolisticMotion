# 两小时追加优化记录（2026-09-25）

本轮接续[三小时优化](optimization_20260925.md)，起点为 `eea0e78`，继续在
`perf/numerical-query-optimization` 分支工作。目标是修复已保留的梯形轨迹拒绝输入、
提高组合状态查询效率，并用更有针对性的输入检查轨迹限位。工作窗口为北京时间
13:14–15:14；改动提交至面向 `main` 的 [PR #3](https://github.com/chase6305/HolisticMotion/pull/3)。

## 已落实的改动

| 范围 | 可复现问题或开销 | 处理 |
| --- | --- | --- |
| 梯形剖面合并 | 极短加减速阶段消失后，位移检查未考虑绝对坐标的舍入；微小速度修正会改变平均速度及所需时间 | 位移预算包含坐标舍入；时间检查计入小速度修正对应的预期变化，保留物理距离及加速度检查 |
| 完整状态查询 | 位置和各阶导数重复计算五次曲线控制点差分及参数幂 | 内置直线和五次曲线共用求值；自定义子类继续通过原有虚函数查询 |
| 短曲线限位 | 一段长时间相位跨越多个几何段，其 65 个均匀样点可能漏掉其中的短曲线 | 反求几何边界对应的实际时间，每个曲线子区间至少检查 65 点，直线子区间检查解析极值 |
| 利用率归约 | 每个状态重复逐关节除法，动态向量有额外分配 | 固定大小 Eigen 向量复用有限倒数；溢出时回退除法及先取根算法 |
| 导数链式法则 | 速度平方/立方先下溢或溢出；jerk 混合项的三倍曲率也可能先溢出 | 异常幂值逐次相乘，混合项合并标量因子并为极端值分开累计二进制指数，保留可表示结果 |
| 时间尺度 | 节点容差以一秒为下限，极短轨迹内部会被吸附到相位端点 | 容差随实际时间戳变化，左侧采样与倒退时间戳检查采用相同尺度 |
| 诊断工具 | 默认随机分布较少覆盖极不等长路径与强各向异性限位 | 增加 `--distribution stress`，均衡覆盖四类路径形状与两种剖面，最高 32 维；构造及查询基准扩展至 20/32 维 |

公开接口、对象数据布局和依赖未改变。没有增加机器人资产、隐式模型下载或核心可视化依赖。
输入仍由调用者提供；测试使用合成路径和临时 URDF。

### 回归依据

上一轮保留的
[`trapezoidal_timestamp_rejection.json`](../benchmarks/fixtures/trapezoidal_timestamp_rejection.json)
已成为 Python 回归输入。对应 C++ 回归独立积分各阶段，不以放宽终点断言掩盖误差。
原来一次极小速度修正被时间预算误拒绝的标量剖面也有独立回归。

短曲线回归使用四个二维路点和强各向异性限位。旧版两种剖面的采样加速度均达到
限制的约 **1.2997 倍**，修复后通过。初始 100,000 组探索性压力输入出现 22 组
采样越限与 58 组构造拒绝；几何细分修复后，99,942 组成功结果全部通过同等采样检查，
58 组仍被拒绝。此计数对应该修复阶段，不能与后续均衡压力分布的计数混用。
另用单个线性、二次、三次时间相位穿过两段极短曲线，通过独立的几何网格
和解析时间反函数核对导数限位，覆盖非匀速阶段的边界反求。

链式法则回归使用独立的时间域多项式：几何导数很大、标量速度很小时，二次运动的
加速度 `2e-100`、三次运动的 jerk `6e-150` 仍应非零。另检查速度 `1e150`、
加速度 `1e300` 的直线梯形轨迹，以及极小限位的倒数溢出和仍有有限根的利用率溢出。
混合 jerk 回归使用 `q(t)=(a*t+b*t²)²` 的解析三阶导数：既覆盖三倍曲率先溢出，
也覆盖标量速度与加速度先相乘下溢，普通和组合查询均检查。2,000,000 组跨指数范围的
混合乘积与扩展精度参考比较；绝对值大于 `1e-300` 的有限参考结果中，
最大相对差约 `3.18e-16`。

节点回归覆盖 `1e-100`、`1`、`1e100` 时间尺度：内部查询保持正确相位，明显倒退
时间戳被拒绝，一个浮点间隔的舍入仍可接受。极短梯形轨迹的全部 101 个样点与解析
位置比较，并检查速度连续性。

## 剩余边界

压力分布仍可能产生构造拒绝。例如，较大累计时间戳之后的极短梯形减速阶段，
受双精度时间分辨率限制，无法同时满足严格的位移积分检查；Double-S 短路径也可能
进入现有的端点速度回溯拒绝分支。相邻段速度上限的舍入差异超过保守预算时，
也仍可能拒绝构造。有限输入不保证当前双精度剖面算法能构造成功。
拒绝单独报告，不计为通过，不为提高通过率而跳过物理约束检查。

曲线限位及连续性审计仍依赖采样，不构成连续可行性或无碰撞证明。没有进行 CUDA
硬件验证或实体机器人试验；碰撞仅在可选组件配置中验证。
