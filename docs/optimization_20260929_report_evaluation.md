## 实现与数值边界

仅 `jet[2] == 0 && jet[3] == 0` 使用新分支。它保留零乘法、零加法、时间缩放
顺序，以及速度幂溢出/下溢时的逐次乘法回退；自定义几何仍调用原有虚函数。
其他时钟保留原来的分步切向量运算。

一般情形不能直接展开为同一系数表达式：令 `e = 2^-27`，分步计算
`(1-e)*(1+e)-1` 得到零，融合乘加则可能得到 `-2^-54`。
新增 32 维回归检查这一抵消边界，以及正负零、正负 `1e200`/`1e-200` 速度、
`1e150` 时间缩放和每阶虚函数调用次数。

Python 基准增加 `--operations report` 与 `--dofs`，可以单独测量报告并选择维度。
默认仍为 110 个状态/均匀采样配置；默认维度下的报告模式有 88 个配置。
报告摘要包含全部诊断字段、数值、形状、dtype、步长、所有权和可写性。
工况闭包显式绑定轨迹及采样参数。

## 验证

- Core：24/24 CTest；Python 1,175 passed / 140 skipped。
- Collision：25/25 CTest；Python 857 passed / 458 skipped。
- ASan/UBSan、Eigen 断言和默认泄漏检查：25/25 CTest。
- Conan 共享包：24/24 测试、标准消费者、旧 main 头文件消费者、链式求导及
  SE3 消费者通过；同一个旧头文件 R1–R32 程序在两套库上输出完全一致。
- 4,500 组随机路径/时钟输入的完整 C++ 报告一致；6,192 个 Python 报告输出
  覆盖全部 32 个关节维度、两种速度剖面、不同尺度、路径混合和时间缩放，
  全部诊断字段及数组元数据一致。
- 131,328 次批量/标量对照、108 个 Cartesian 配置、既有 20,000 个 Rn 指纹
  及全部 Python 公共方法文档签名保持一致。
- 同一组 1,224,720 个极端算术输入在默认与 `-march=native` 下各运行一次；
  有限结果、非有限类别及零符号一致。另在匹配 Eigen 配置后，以本机指令集
  编译的新增/既有链式求导回归在基线和候选共享库上均通过。
- C++ 594 个配置的报告分配次数仍为 8；Python 198 个配置的分配次数不变。
- 独立重算 1,184 份主测量 CSV 的 2,350 项计时汇总；另核查逐工况复测的
  352 份 CSV、110 项汇总。中位数、范围、配对比例和非计时字段均一致。
- 基准 CLI、非法参数、Ruff 和严格中英文文档构建通过。新增测试/基准不需要
  外部机器人资产；加载机器人仍由调用方显式提供 URDF 路径。

本机指令集消费者复查显式匹配共享库的 16 字节 Eigen 对齐与 malloc/free 策略，
并隐藏调用方内联符号。最初混用默认库和不同 Eigen 配置时，基线也会失败；
这些测试程序配置错误及修正过程单独保存，不算作算法回归。独立算术语料没有
跨越这一 ABI 边界。动态符号变化包含头文件内联及内部模板实例，不能据消费者
通过就声称整个导出符号集合完全相同。

## 未采用的实验与复现

一般链式求导的系数展开在本机指令集下改变浮点结果，未采用。稀疏均匀采样改走
逐点查询、缓存引用计数调整、二次曲线专用分支，以及报告直接写 NumPy/固定尺寸
报告等方案也未采用。直接报告缓冲区原型确实减少了 8 次堆分配，但没有获得可接受
的整体耗时结果。部分探索计时存在进程重叠，另有同进程动态符号实验；这些都与
最终 `measured-*` 数据分开保存，不用于上表结论。

```bash
PYTHONPATH=build/install python benchmarks/python_trajectory_benchmark.py \
  --operations report --dofs 1 4 32 --repeats 9
ctest --test-dir build/hour-core --output-on-failure
conan create . --no-remote -o '&:with_python=False' -o '&:shared=True' \
  -o '&:with_tests=True' -o '&:with_collision=False' -o '&:with_cuda=False' \
  -c tools.build:jobs=2
```
